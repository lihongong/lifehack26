# Issue #8 implementation context

## User outcome

An authenticated Participant can privately select one canonical NUS Zone, explicitly opt into Buffet Alerts, and receive one in-app alert for each fresh Buffet Post in that zone or one adjacent graph hop away.
Repeated delivery or edits of the same Buffet Post must not create another alert for the same Participant.
A Participant can mark a received Buffet Alert helpful or report that its food is gone.
A food-gone report must suppress later alerts for that Buffet Post, mark the post possibly gone, and create work for a Moderator.
Moderator restoration or expiry must be audited, and either feedback path must record a Helpful Alert outcome.

## Acceptance criteria

- The initial Participant location is unset and Buffet Alerts are off.
- An authenticated Participant can explicitly select exactly one canonical NUS Zone and opt in.
- Fresh Buffet Posts in the selected NUS Zone or one adjacent NUS Zone create a single in-app alert.
- Buffet Post edits and duplicate deliveries do not duplicate an existing Participant alert.
- Reporting food gone suppresses later alerts, exposes a possibly-gone state, and enters Moderator review.
- Moderator restoration or expiry creates an immutable audit event.
- Helpful and food-gone feedback each record the Helpful Alert outcome.

## Existing Buffet behavior

`backend/src/data/demoBuffetPosts.js` creates fictional Buffet Post objects once from an application-startup anchor.
`backend/src/app.js` injects that array into `buffetRoutes`, and the current Buffet feed is not persisted in SQLite.
`backend/src/services/buffetService.js` derives public expiry, filters expired posts, applies exact-zone and freshness filters, and returns public zone graph metadata.
`backend/src/routes/buffetRoutes.js` currently exposes only anonymous `GET /api/buffets`.
`frontend/src/components/BuffetFeed.jsx`, `frontend/src/components/BuffetFilters.jsx`, `frontend/src/components/BuffetCard.jsx`, and `frontend/src/hooks/useBuffets.js` implement the anonymous feed and its 30-second refresh.
`test/buffetService.test.js` verifies aliases, graph integrity, filtering, expiry boundaries, and safe public API metadata.
`e2e/buffets.spec.js` verifies the anonymous Buffet journey on both configured mobile and desktop projects.

## NUS Zone behavior

`backend/src/data/nusZones.js` defines `nus-zones-v1`, ten canonical zones, approved aliases, and an undirected graph.
`adjacentZoneIds` returns exactly one graph hop and `publicZones` includes adjacency metadata.
`backend/src/services/participantService.js` currently validates profile zones against the older values `Kent Ridge`, `Bukit Timah`, and `Outram`, which do not match the canonical `nus-zones-v1` identifiers.
`frontend/src/components/ProfileForm.jsx` exposes those same older values plus an unset option.
The participant table already has a nullable private `nus_zone` column, so existing and new profiles can represent the required unset initial state.

`backend/src/routes/devRoutes.js` explicitly resets persistent tables and recreates immutable triggers, so new persistent alert and review state must be included in the development reset path.

## Data and interface constraints

The Buffet Post source objects have stable `id`, `sourceTime`, zone, and expiry data but no current database lifecycle or delivery event endpoint.
The issue requires deduplication across edits and duplicate deliveries, so the persistent seam must distinguish a stable Buffet Post identity from changing content.
Location-unclear Buffet Posts have no canonical zone and therefore cannot match a selected or Nearby Zone.
Expiry is already deterministic at the stated deadline or the two-hour fallback boundary.
The issue does not define a Gem award for alerts or feedback, and existing protected Comment and Content Report actions deliberately avoid creating Gem Ledger entries.
The selected NUS Zone and alert preference are private profile state and must not be added to public Participant or anonymous Buffet responses beyond the existing public zone graph metadata.
