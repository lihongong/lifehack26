# Repository agent instructions

## Writing and commits

- Use plain hyphens (`-`) instead of em dashes.
- Write commit messages without autogenerated agent names or `Co-authored-by` attribution.
- Resolve every GitHub issue from a new issue-specific branch created from the latest remote `main`.
  Push that branch and open a pull request containing `Closes #N`; never resolve a new issue directly on `main` or reuse another issue's branch.
- Treat `CHANGELOG.md` and files marked as autogenerated as generated artifacts.
  Update them only through their generators.
- When writing or substantially editing long Markdown files, put each full sentence on its own physical line.
  Preserve normal Markdown structure and avoid placing multiple sentences on one physical line.

## Engineering quality

- Prefer quality, simplicity, robustness, scalability, and long-term maintainability over development cost when making technical decisions.
- Begin bug fixes by reproducing the bug in an end-to-end setting that matches the end-user experience as closely as possible.
  Confirm the reproduction fails before implementing the fix so the test demonstrates that the real problem was solved.
- Be exacting about the visible UI during end-to-end testing and maintain pixel-level quality.
  If something clearly looks wrong, fix it along the way even when it is not directly related to the current task.
- Apply the same standard to engineering quality, including lint failures, test failures, and flaky tests.
  Fix issues you encounter even when the current work did not cause them.
